# F5.7b-R Railway to Supabase runtime result

Status: `ELIGIBLE` for the F5.7b-R deployment-path gate.

This result measures the production PostgreSQL lease/outbox/repository path from an
isolated Railway service in `ams` to the Supabase session pooler. Telegram delivery
remained a deterministic fake provider. It is not Telegram capacity evidence and
must not be used as the final production sizing decision.

## Reproducibility

- GitHub commit and `F57B_COMMIT`: `9023d60`
- Runtime image: Node `v22.23.2`, Debian bookworm slim
- Railway service: dedicated `f57b-postgres-benchmark`, one replica in `ams`
- Matrix: `1:1`, `10:1`, `10:5`, `25:5`, `50:10`
- Samples: 1 warm-up + 3 measured samples per case
- PostgreSQL client pool: 12 maximum connections; 15-second connect timeout
- Provider latency: 0 ms fake adapter latency
- Per-sample executor timeout: 60 seconds
- Structured result: 331 records; 165/165 hard assertions passed; 0 failed
- Deployment result: `SUCCESS`

No database URL, password, Telegram API credential, or Telegram session is present
in the result or this report.

## Correctness and cleanup gates

- Every one of the 165 hard assertions passed.
- The run emitted one completion record with `passed=true`; no automatic benchmark
  retry was used.
- A live mid-run query observed the expected temporary `25:5` fixture and active
  leases, proving the container was executing the database path rather than waiting.
- A post-run Supabase query returned zero operations, commands, Telegram accounts,
  worker assignments, auth fixture users, and active account leases.
- The first deployment failed before opening PostgreSQL because its old image omitted
  repository-relative packages. The corrected fresh GitHub build copied both internal
  packages and completed; the failed image was not reused as evidence.

## Interpretation boundary

F5.7b-R proves the selected Railway container/region can execute and clean up the
production database path. F5.7c still must measure distinct controlled Telegram
sessions, reconnect/error behavior, and the 1-hour then 24-hour soak before F5.7d can
set account concurrency, replica sizing, or a production capacity envelope.
